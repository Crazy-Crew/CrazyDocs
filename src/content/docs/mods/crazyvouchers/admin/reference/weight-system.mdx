<Aside type="tip">
    The system in the simplest form is that the higher the `weight` option, the more likely that entry's commands will run.

    It's similar to having a pool with 45 tickets labeled "Gold" and 5 tickets labeled "Netherite". You pull one ticket, and "Gold" comes up 9 times as often.
</Aside>

**`random-commands` is a section on a voucher or a code. Each entry in it has a `commands` list and an optional `weight` option.**

The section runs two picks that are independent of each other:

- **Weighted pick:** the entries with a `weight` above `0` compete, and one of them runs based on its weight.
- **Random pick:** the entries without a `weight` compete, and one of them runs, each with the same chance.

### 1. Where does it go?
<Tabs>
    <TabCard label="Voucher">
        `random-commands` sits under the root `voucher:` key, as in the shipped `vouchers/Example.yml`.

        ```yml

        item: 'diamond_helmet'
        # The commands to send.
        commands:
        - 'msg {player} wow you claimed a voucher.'
        random-commands:
        "1":
        # The chance for these to run
        weight: 45.0
        # The commands to run
        commands:
        - "give {player} gold_ingot {random}:1-5"
        "2":

        weight: 25.0
        # The commands to run
        commands:
        - "give {player} iron_ingot {random}:5-10"
        "3":
        # The chance for these to run
        weight: 15.0
        # The commands to run
        commands:
        - "give {player} emerald {random}:16-32"
        "4":
        # The chance for these to run
        weight: 10.0
        # The commands to run
        commands:
        ```

<Aside type="note">
    The entry names (`"1"`, `"2"` and so on) are only labels, you can name them anything.

    When an entry is picked, every line in its `commands` list runs from the console. The `{random}:1-5` in these commands is a placeholder, not part of the weight system. Check out [Placeholders](/mods/crazyvouchers/reference/placeholders/) for more.
</Aside>

### 2. How is an entry picked?
<Tabs>
    <TabCard label="Weighted pick">
        Only entries with a `weight` above `0` take part.

        The max range is the sum of those weights. The plugin rolls a random number between `0` and that sum, then subtracts each entry's weight in order until it lands on one. Each entry's chance is its weight divided by the sum.

        Weights are relative to each other, so they do not need to add up to 100. The shipped example adds up to exactly 100, so each weight reads as a percentage:

        | Entry | `weight` | Chance |
        |-------|----------|--------|
        | `"1"` | `45.0`   | 45%    |
        | `"2"` | `25.0`   | 25%    |
        | `"3"` | `15.0`   | 15%    |
        | `"4"` | `10.0`   | 10%    |
        | `"5"` | `5.0`    | 5%     |

        Exactly one weighted entry runs per use.
    </TabCard>
    <TabCard label="Random pick">
        Only entries without a `weight` take part. One of them runs, each with the same chance.

        In the shipped example, `"6"` is the only entry without a `weight`, so it runs on every use, on top of the weighted pick.
    </TabCard>
    <TabCard label="Order">
        When a voucher is used or a code is redeemed, the plugin runs:

        1. Every line in `commands`.
        2. The random pick, if it has any entries.
        3. The weighted pick, if it has any entries.

        At most two entries from `random-commands` run per use: one from each pick.
    </TabCard>
</Tabs>

<Aside type="note">
    Both picks use Java's `Random` by default. Set `root.use-different-random: true` in `config.yml` to use `ThreadLocalRandom` instead.
</Aside>

### 3. Tips
- Leave the `weight` option out to put an entry in the random pick.
- Give every weighted entry a `weight` above `0`.
- Files that still use the old list form of `random-commands` or `chance-commands` can be converted with `/crazyvouchers migrate -mt VouchersDeprecated`.
